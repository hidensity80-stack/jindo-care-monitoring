# 진도군 통합돌봄 모니터링 시스템

진도군 통합돌봄 7개 서비스(목욕, 가사, 식사(도시락), 미용, 이동, 스마트돌봄, 방문의료)를 받는 어르신 약 600명의
**월간 계획 → 승인 → 현장 기록 → 실시간 모니터링 → 위험 대응**을 한 곳에서 관리하는 시스템입니다.
담당자가 자리를 비우거나 업무에 익숙하지 않을 때 켜서 쓰는 **AI 당직·AI 도우미** 기능이 있고, AI 모델은 설정에서 바꿀 수 있습니다.

> ⚠️ 이 저장소의 이름, 연락처, 병원명, 수치는 모두 **가상의 예시 데이터**입니다. 실제 개인정보는 커밋하지 마세요.

**프로젝트 상태**: 시제품 완성(시연 가능) · PHP 서버 버전 1차 개발 중 — 자세한 내용은 [14. 프로젝트 상태](#14-프로젝트-상태)

**목차**: [1. 접속 주소](#1-접속-주소) · [2. 주요 기능](#2-주요-기능) · [3. 작동 방법](#3-작동-방법-업무-흐름) · [4. 실행 방법](#4-실행-방법) · [5. 폴더 구성](#5-폴더-구성) · [6. 기술 구성](#6-기술-구성) · [7. 저장소 관리](#7-저장소-관리-gitlab) · [8. 알아 두실 점](#8-알아-두실-점) · [9. 시연 자료](#9-시연-자료) · [10. 향후 계획](#10-향후-계획) · [11. 수정·기여 방법](#11-수정기여-방법) · [12. 문의](#12-문의) · [13. 만든 사람과 라이선스](#13-만든-사람과-라이선스) · [14. 프로젝트 상태](#14-프로젝트-상태)

## 2. 주요 기능

### 대시보드 (총괄 담당자)
| 화면 | 기능 |
|---|---|
| **일간** | 오늘 계획·완료·진행중·지연·미수행·취소·건강이상 건수, 어르신 × 7개 서비스 상태표, 담당자 타임라인, 주의 필요 알림, 실시간 수행 기록 |
| **월간** | 달력으로 날짜별 계획·실적, 보기 전환(전체 / 서비스별 / 담당자별 / 개인별), 계획 승인 상태 |
| **연간** | 서비스별 누적 제공·이행률·이용자 수, 월별 추이 그래프, 서비스 × 월 이행률 표, 읍·면별·수행기관별 실적 |
| **어르신 상세** | 이용 서비스와 담당자, 그날 일정, 최근 30일 건강상태, 위험 판단 근거, 이상 보고 이력 |
| **집중관리** | 최근 14일 기록으로 위험·주의·관심 자동 분류, 처리 상태와 조치 메모 |
| **퇴원지원** | 퇴원환자 지원 신청 목록(퇴원일 가까운 순), 단계 처리, 상담 메모, 전화 접수 대리 입력 |
| **계획 승인** | 기관별 다음 달 계획 승인·반려(자동 점검 결과 포함), 확정 일정의 변경 요청 승인·반려 |
| **계정 관리** | 수행기관 관리자·조회 전용 계정 발급, 비밀번호 초기화, 사용 정지 |
| **알림 띠** | 화면 맨 위에 새 퇴원지원 신청(주황)과 긴급 상황(빨강)을 표시하고, 그 자리에서 처리 |

### 수행기관 관리자
- **오늘 현황**: 우리 기관 방문 현황만 표시
- **월간 계획**: 이용 규칙(예: 매주 화·목)으로 만들어진 초안 → 일정 고치기 → 자동 점검 → 제출
  - 일괄 작업: 날짜 일괄 이동(공휴일), 담당자 일괄 이관(휴가·퇴사), 일정 추가(이동 지원 등)
  - 자동 점검: 계약 횟수 미달, 같은 담당자 시간 겹침, 일요일 일정
- **수행자 계정**: 소속 현장 수행자 계정 생성·정지·비밀번호 초기화

### 현장 수행자 (휴대폰 화면)
- 오늘 방문 목록: **[방문 시작] → [종료·상태 입력]** (건강상태 좋음·보통·나쁨 + 징후 + 메모), 취소(사유)
- **일정 변경 요청**, **[긴급]** 알리기
- 화면 아래 **월별 방문 달력**: 날짜를 누르면 그날 방문할 어르신 목록, 예정 일정 변경 요청

### 누구나 (로그인 없이)
- **통합돌봄 퇴원환자 지원 신청**: 본인·보호자·병원이 신청(개인정보 동의 필수) → 접수번호 발급
- **진행 상황 확인**: 접수번호와 환자 이름으로 현재 단계 조회

### 시스템 관리자
- 모든 계정 관리, **접속기록**(로그인·어르신 정보 조회·기록·계획·계정 변경 이력)
- **AI 설정**: AI 연결·교체, 기능별 모델 지정, AI 당직 권한 (아래 AI 기능 참고)

### AI 기능 (켜고 끌 수 있음)
AI를 꺼도 위험 판정·긴급 알림·지연 표시는 지금처럼 **규칙대로 계속 작동**합니다. AI는 정리·연락·초안·안내를 돕고, 결정은 담당자가 합니다.

| 기능 | 누가 | 내용 |
|---|---|---|
| **AI 당직** | 총괄 담당자·시스템 관리자 | 자리를 비울 때 위쪽 **[AI 당직 켜기]**. AI가 긴급·방문 지연·건강 '나쁨'·퇴원 신청·변경 요청·계획 제출을 감시하고 정리합니다. 허용한 일(지연 시 수행자에게 확인 메시지, 퇴원 신청인에게 접수 확인 문자 등)만 실행하고, 나머지는 담당자에게 넘깁니다. 긴급 상황은 비상 연락처에 바로 알립니다. |
| **부재 중 보고** | 총괄 담당자·시스템 관리자 | 당직 중에 다시 로그인하면 "부재 중 AI 당직 보고"가 먼저 열립니다. 담당자가 확인할 일(급한 순)과 AI가 처리한 일을 나눠 보여 주고, 항목마다 [조치 입력]·[처리하기]·[확인함] 버튼이 있습니다. |
| **AI 도우미** | 총괄·수행기관·관리자·조회 | 화면 오른쪽 아래 **[AI 도우미]** 대화창. 화면 설명, 지금 먼저 처리할 일, 어르신 찾기(예: "의신면 독거 위험 어르신"), 지연·건강 현황, 긴급·퇴원지원 처리 방법, 보호자 안내 문자·업무 보고서 초안 |
| **AI 초안** | 총괄 담당자 | 긴급 조치·퇴원지원 처리 창의 **[AI 초안]** 버튼으로 메모 초안 작성. 확인 안 된 내용은 [ ]로 비워 둠 |
| **실수 막기** | 총괄 담당자 | 자동 점검에 문제가 있는 계획을 승인하려 하면 한 번 더 확인 |
| **AI 설정** | 시스템 관리자 | 연결 추가·수정(종류: OpenAI 호환·Anthropic·Google, 주소, 모델 이름, API 키), [시험], 기능별 주 모델·예비 모델, 연결별 개인정보 전송 허용·금지, 가명처리, 하루 사용 한도, 당직 단계(1 알려 주기 · 2 초안 쓰기 · 3 정해진 일 실행), 허용할 일, 비상 연락 순서, 근무시간 외 자동 켜기, 기능별 지시문 |

- AI가 한 일과 AI 설정 변경은 모두 접속기록에 남습니다(아이디 `AI 당직`).
- 현장 수행자 화면(휴대폰)에는 AI 기능이 나오지 않습니다.

## 3. 작동 방법 (업무 흐름)

```
수행기관: 월간 계획 작성·제출 ──▶ 총괄 담당자: 승인(확정) / 반려
                                          │
현장 수행자: 방문 시작·종료·건강상태 기록 ──▶ 대시보드 실시간 반영 ──▶ 위험 자동 판정 ──▶ 집중관리·조치
        └─ [긴급] ─────────────────────────────▶ 총괄 화면 알림 띠 ──▶ 조치 입력
누구나: 퇴원환자 지원 신청 ──▶ 총괄 화면 알림 띠 ──▶ 상담·욕구조사 → 서비스연계 → 종결
담당자 부재: [AI 당직 켜기] ──▶ AI가 감시·정리·허용된 연락 ──▶ 판단이 필요한 일은 인계 ──▶ 복귀 로그인 시 부재 중 보고
```

### 따라 해 보기 (약 5분)

1. **수행기관이 계획 제출** — `org2`(가사)로 로그인 → [월간 계획] → 표의 숫자 칸을 눌러 일정 고치기 → [점검 확인하고 제출하기]
2. **총괄 담당자가 승인** — 로그아웃 후 `central`로 로그인 → [계획 승인] → 가사 계획 [승인] / 다른 기관 [반려](사유 입력) → 아래 변경 요청 [승인]
3. **현장 수행자가 방문 기록** — 로그인 화면의 **현장 수행자** 버튼 → [방문 시작] → [종료·상태 입력]에서 **나쁨** 선택 후 저장 → [긴급] 눌러 알리기
4. **총괄 담당자가 확인·조치** — `central`로 로그인 → 맨 위 빨간 긴급 띠 [조치 입력] → [일간]에서 방금 기록한 "건강이상" 확인
5. **퇴원환자 지원 신청과 처리** — 로그인 화면 [신청 페이지로 가기] → 신청서 작성·동의 → 접수번호 확인 → `central`로 로그인 → 주황 알림 띠 [처리하기] → 단계와 처리 내용 저장
6. **기록 확인** — `admin`으로 로그인 → [접속기록]에서 지금까지 한 일 확인
7. **AI 당직과 도우미** — `central`로 로그인 → 위쪽 [AI 당직 켜기] → [AI 당직 시작] → 보라색 띠에서 [당직 기록 보기] → 로그아웃 후 다시 `central`로 로그인하면 "부재 중 AI 당직 보고"가 열림 → [당직 끄고 업무 시작] → 오른쪽 아래 [AI 도우미]에서 "지금 먼저 처리할 일", "의신면 독거 위험 어르신" 눌러 보기
8. **AI 모델 바꾸기** — `admin`으로 로그인 → [AI 설정] → [연결 추가]에서 주소·모델 이름·키 입력 → [시험] → "기능별 모델 지정"에서 새 연결 고르기

### 화면 표시 규칙

| 상태 | 색 | 기준 |
|---|---|---|
| 예정 | 회색 | 아직 시작 전 |
| 진행중 | 파랑 | 시작 기록 있음 |
| 완료 | 초록 | 종료 + 건강상태 기록 (점 색: 좋음 초록 · 보통 노랑 · 나쁨 빨강, `!` 이상 보고) |
| 지연 | 주황 | 예정 시각에서 30분이 지나도 시작 안 함 |
| 미수행 | 빨강 | 지난 날인데 완료 기록 없음 |
| 취소 | 진회색 | 사유와 함께 취소 |

**위험 판정 (최근 14일)**: '나쁨' 1회 2점 · 서로 다른 서비스 2곳 이상 이상 보고 4점 · 미수행 1점 · 오늘 지연 2점 · 독거+이상 보고 1점
→ 10점 이상 **위험**, 6점 이상 **주의**, 3점 이상 **관심**

**퇴원지원 처리 단계**: 접수 → 상담·욕구조사 → 서비스연계 → 종결 (퇴원 3일 이내는 주황 테두리)

### 화면 오른쪽 위 버튼
- **시간 멈춤 / 시간 흐름**: 시제품은 오늘 현황을 시뮬레이션합니다(3초에 1분씩 흐름).
- **초기화**: 이 브라우저에 저장된 내용을 지우고 처음 예시 상태로 되돌립니다.

## 4. 실행 방법

### ① 온라인 (권장)
위 **접속 주소**를 브라우저로 엽니다.

### ② 내 PC에서 (서버 없이)
저장소를 내려받은 뒤 `prototype/index.html`을 더블클릭합니다.

### ③ GitHub Pages로 다시 배포할 때
GitHub 저장소 → Settings → Pages → Branch `main`, 폴더 `/ (root)` → Save
(루트의 `index.html`이 `prototype/`으로 자동 이동시킵니다.)

### ④ PHP 서버로 실행 (운영용 1차 버전)
PHP 8.0 이상과 `pdo_sqlite`, `mbstring` 확장이 필요합니다.

```bash
cd server-php
cp config.example.php config.php    # Windows: copy config.example.php config.php
php install.php                     # 테이블 생성 + 예시 데이터 입력 (1~2분)
php -S localhost:8080
```

브라우저에서 `http://localhost:8080/login.php`를 엽니다. MySQL 사용, Apache(XAMPP) 설치 등은 [server-php/README.md](server-php/README.md)를 참고하세요.

## 7. 저장소 관리 (GitLab)

저장소 주소: `https://gitlab.aigov.go.kr/JINDO428/jindo-care-monitoring.git`

### 처음 올릴 때
다운로드 받은 `jindo-care-monitoring` 폴더를 그대로 사용합니다.

```bash
cd ~/Downloads/jindo-care-monitoring
git init
git add .
git commit -m "진도군 통합돌봄 모니터링 시스템"
git remote add origin https://gitlab.aigov.go.kr/JINDO428/jindo-care-monitoring.git
git branch -M main
git push -uf origin main
```

> `-f`(강제 올리기)는 GitLab이 프로젝트를 만들 때 자동으로 넣은 기본 README를 이 README로 덮어씁니다. **처음 한 번만** 쓰고, 이후에는 `git push`만 사용하세요.

### 이미 GitHub에 올린 폴더라면
원격 주소만 하나 더 추가해 두 곳을 함께 관리합니다.

```bash
git remote add gitlab https://gitlab.aigov.go.kr/JINDO428/jindo-care-monitoring.git
git push -uf gitlab main
```

이후 수정할 때마다 `git push origin main`(GitHub, 접속 주소에 반영)과 `git push gitlab main`(GitLab, 소스 보관)을 함께 실행합니다.

### 올리지 않는 파일
- `server-php/config.php`와 `server-php/data/`(DB 파일)는 `.gitignore`로 제외됩니다.
- 시연영상(MP4)은 용량이 커서 저장소에 넣지 않았습니다.

## 8. 알아 두실 점

- **시제품은 데이터를 공유하지 않습니다.** 휴대폰에서 낸 신청이나 기록은 그 휴대폰 브라우저에만 남습니다. 여러 사람이 함께 쓰려면 PHP 서버 버전을 써야 합니다.
- 공개 저장소·공개 주소에서는 누구나 코드와 체험 계정 비밀번호를 볼 수 있습니다. 실제 운영 서버에서는 `DEMO_MODE`를 끄고 모든 비밀번호를 바꾸세요.
- 이 GitLab 저장소에는 실제 어르신 정보, 운영 서버 비밀번호, `config.php`를 올리지 마세요.
- **AI 기능은 시제품에서 예시 답변으로 동작합니다.** 외부 AI를 실제로 부르지 않고, [AI 설정]에 넣은 API 키도 저장하지 않습니다(끝 4자리만 기억). 실제 AI 연결은 PHP 서버 버전에서 해야 하며, **API 키를 시제품이나 저장소에 넣지 마세요.** 공개 주소에서 누구나 볼 수 있습니다.
- AI 답변은 참고용입니다. 어르신 건강 정보를 다루므로 운영 전에 개인정보 처리가 승인된 AI(정부·군청 내부 AI 등)를 쓰고, 개인정보 영향평가와 행정안전부 공공부문 AI 활용 지침을 확인하세요.

## 11. 수정·기여 방법

1. 할 일이나 오류는 GitLab **이슈**로 등록합니다.
2. `main`에서 작업 브랜치를 만들어 고칩니다. 예: `git checkout -b fix/일간-지연표시`
3. 고친 뒤 브라우저로 `prototype/index.html`을 열어 확인합니다. 화면 오른쪽 위 **[초기화]**로 처음 상태에서 다시 확인할 수 있습니다.
4. GitLab에 올리고 **머지 요청(Merge Request)** 을 만듭니다. 담당자가 확인한 뒤 `main`에 합칩니다.
5. 접속 주소에 반영하려면 GitHub 저장소에도 올립니다([7장](#7-저장소-관리-gitlab)).

- 시제품 화면 코드는 `prototype/assets/app.js`, AI 기능은 `prototype/assets/ai.js`, 디자인은 `prototype/assets/style.css`에 있습니다.
- 커밋 메시지는 한국어로, 무엇을 왜 바꿨는지 한 줄로 적습니다.
