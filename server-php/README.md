# 진도군 통합돌봄 모니터링 (PHP 시제품)

7개 돌봄 서비스(목욕, 가사, 식사(도시락), 미용, 이동, 스마트돌봄, 방문의료)의 계획·수행 현황을
연간/월간/일간 대시보드로 보여 주고, 현장 담당자가 휴대폰으로 방문 시작·종료·건강상태를 입력하는 PHP 프로그램입니다.

> 시제품입니다. 구축계획서 1차 범위(계정·권한·접속기록, 계획 제출·승인, 대시보드, 현장 앱, 위험 감지)와
> 2차 범위 중 긴급 버튼을 담았습니다. 운영 전 "운영 전 꼭 보완할 것"을 확인하세요.

## 역할과 처음 화면

로그인하면 역할에 맞는 화면으로 바로 이동하고, 그 역할에 필요한 탭만 보입니다.

| 역할 | 처음 화면 | 보이는 탭 / 할 수 있는 일 |
|---|---|---|
| 총괄 담당자 | 대시보드 | 일간·월간·연간, 집중관리·발굴, **계획 승인**(제출된 계획 승인·반려, 일정 변경 요청 처리), 계정 관리(기관 관리자·조회 전용) |
| 수행기관 관리자 | 대시보드(자기 기관만) | 오늘 현황, **월간 계획**(초안 → 고치기 → 점검 → 제출), 월간 실적, 연간, 수행자 계정 |
| 현장 수행자 | 현장 앱 | 오늘 방문: 시작·종료·건강상태, 취소, **일정 변경 요청**, **긴급**, 이웃 발굴신고 |
| 시스템 관리자 | 대시보드 | 총괄 담당자 기능 + 모든 계정 관리 + **접속기록** |
| 조회 전용 | 대시보드 | 일간·월간·연간·집중관리 보기만 |

- 화면마다 위쪽에 "이 화면에서 할 일" 안내가 나옵니다([알겠어요]를 누르면 다시 안 보임).
- 현장에서 [긴급]을 누르면 총괄 담당자와 해당 기관 화면 맨 위에 빨간 알림 띠가 뜨고, 조치 내용을 적어야 사라집니다.
- 처음 로그인하거나 비밀번호를 초기화한 계정은 비밀번호를 바꿔야 쓸 수 있습니다.
- 비밀번호 5회 오류 시 10분 잠김, 관리자 화면은 30분·현장 앱은 12시간 미사용 시 자동 로그아웃.
- 로그인, 어르신 정보 조회, 기록·계획·계정 변경은 모두 접속기록에 남습니다.

### 체험용 계정 (데모 모드)

로그인 화면에 버튼으로 나옵니다. 비밀번호는 모두 `jindo1234`입니다.

| 아이디 | 역할 |
|---|---|
| `central` | 총괄 담당자 |
| `org1` ~ `org7` | 수행기관 관리자 (1 목욕, 2 가사, 3 식사, 4 미용, 5 이동, 6 스마트돌봄, 7 방문의료) |
| `w001` ~ `w210` | 현장 수행자 (서비스별 30명: 가사는 `w031`~`w060`) |
| `admin` | 시스템 관리자 |
| `viewer` | 조회 전용 |

설치 직후 다음 달 계획은 기관마다 상태가 다르게(제출·작성중·반려·승인) 들어 있어 승인 흐름을 바로 체험할 수 있습니다.
변경 요청 2건과 긴급 1건도 예시로 들어 있습니다.

## 구성

| 파일 | 역할 |
|---|---|
| `login.php` / `logout.php` | 로그인·로그아웃 (데모 모드에서는 체험 계정 버튼 표시) |
| `index.php` | 대시보드 (역할별 탭) |
| `field.php` | 현장 앱 (로그인한 수행자의 오늘 일정) |
| `api.php` | 대시보드·현장 앱이 쓰는 JSON API |
| `install.php` | 테이블 생성 + 예시 데이터 입력 (수혜자 600명, 담당자 210명, 올해 일정, 지난 수행기록) |
| `make_schedules.php` | 이용 규칙에 따라 방문 일정 생성 (예: 내년 일정) |
| `config.php` | DB 연결, 데모 모드, 위험 판정 점수 |
| `lib/core.php` | 공통 함수 (상태 계산, 일정 생성, 위험 판정, 데모 기록) |
| `assets/` | 화면 스타일과 스크립트 |
| `data/` | SQLite DB 파일이 생기는 곳 (웹 접근 차단) |

## 필요 환경

- PHP 8.0 이상
- PHP 확장: `pdo_sqlite`(기본 설정) 또는 `pdo_mysql`, 그리고 `mbstring`
- 웹서버: Apache, Nginx 또는 PHP 내장 서버

## 설치 (가장 쉬운 방법: PHP 내장 서버)

```bash
cd jindo-care-php
php install.php
php -S localhost:8080
```

브라우저에서 `http://localhost:8080/index.php`(대시보드)와 `http://localhost:8080/field.php`(현장 앱)를 엽니다.
`install.php`는 지난 수행기록까지 만들기 때문에 1~2분 걸릴 수 있습니다.

### XAMPP 등 Apache에 올릴 때

1. 폴더를 `htdocs/jindo-care-php`에 복사합니다.
2. `config.php`의 `INSTALL_KEY`를 바꿉니다.
3. `http://localhost/jindo-care-php/install.php?key=바꾼키`를 엽니다 (또는 명령줄에서 `php install.php`).
4. 설치가 끝나면 `install.php`를 삭제합니다.
5. `data/` 폴더에 웹서버 쓰기 권한이 있어야 합니다.

### MySQL / MariaDB를 쓸 때

`config.php`에서 아래처럼 바꾸고, DB를 먼저 만든 뒤 `install.php`를 실행합니다.

```php
'DB_DSN'  => 'mysql:host=127.0.0.1;dbname=jindo_care;charset=utf8mb4',
'DB_USER' => '계정',
'DB_PASS' => '비밀번호',
```

## 데모 모드

`config.php`의 `DEMO_MODE`가 `true`이면, 화면을 열 때마다 오늘 일정의 수행기록(시작·종료·건강상태)이
현재 시각에 맞춰 자동으로 채워집니다. 일부는 일부러 취소·지연·미수행·건강이상이 되도록 만들어 집니다.

- 현장 앱을 직접 눌러 보려면, 아직 시각이 오지 않은 일정(오후 일정 등)을 고르거나
  설치 후 `DEMO_MODE`를 `false`로 바꾸세요. 그러면 이미 만들어진 기록은 남고, 오늘 이후 기록은 현장 앱 입력으로만 쌓입니다.
- 운영 시에는 반드시 `false`로 두세요.

## 화면 요약

- **연간**: 서비스별 누적 제공 건수, 이행률, 월별 추이 그래프, 서비스 × 월 이행률 표, 읍·면별·수행기관별 실적
- **월간**: 달력 (전체 / 서비스별 / 담당자별 / 개인별 보기), 이번 달 실적, 다음 달 계획 등록 현황
- **일간**: 수혜자 × 7개 서비스 상태표, 담당자 타임라인, 주의 필요 알림, 실시간 수행 기록 (30초마다 자동 갱신)
- **집중관리·발굴**: 위험·주의·관심 자동 판정, 처리 상태·조치 메모, 발굴신고 접수함과 접수 양식

### 상태 판정 기준

| 상태 | 기준 |
|---|---|
| 예정 | 오늘 일정, 아직 시작 전 |
| 진행중 | 시작 기록 있음, 종료 전 |
| 완료 | 종료 기록 있음 (건강상태 포함) |
| 지연 | 예정 시각에서 30분이 지나도 시작 기록 없음 |
| 미수행 | 지난 날짜인데 완료 기록 없음 |
| 취소 | 취소 사유와 함께 기록됨 |

### 위험 판정 (config.php `RISK`에서 조정)

최근 14일 기록으로 점수를 계산합니다.
'나쁨' 1회당 2점, 서로 다른 서비스 2곳 이상에서 이상 보고 시 4점, 미수행 1점, 오늘 지연 2점, 독거이면서 이상 보고 1점.
합계 10점 이상은 위험, 6점 이상은 주의, 3점 이상은 관심입니다.

## 데이터 구조

| 테이블 | 내용 |
|---|---|
| `services` | 서비스 7종, 수행기관, 기본 시작 시각·소요 시간, 서비스별 이상 징후 목록 |
| `recipients` | 수혜자 (번호, 이름, 나이, 읍·면, 가구 형태) |
| `workers` | 수행기관 담당자 |
| `enrollments` | 수혜자별 이용 서비스, 담당자, 이용 규칙(JSON, 예: 매주 화·목) |
| `schedules` | 날짜별 방문 일정 (이용 규칙으로 생성) |
| `visits` | 현장 앱 수행기록 (시작·종료 시각, 건강상태, 징후, 메모, 위치) |
| `care_cases` | 집중관리 처리 상태와 메모 |
| `reports` | 발굴신고 |
| `users` | 계정 (아이디, 암호화된 비밀번호, 역할, 소속 기관, 연결된 담당자, 사용 여부) |
| `plans` | 기관 × 월 계획 상태 (작성중·제출·승인·반려), 제출·승인 일시와 처리자 |
| `change_requests` | 확정된 일정의 변경 요청과 처리 결과 |
| `emergencies` | 현장 긴급 신고와 조치 내용 |
| `audit_logs` | 접속기록 (로그인, 조회, 변경) |

`recipients.demo_risk`, `demo_trend`, `workers.demo_slack` 열은 데모 기록을 만들 때만 씁니다.

## 운영 전 꼭 보완할 것

1. **체험 계정 정리**: `DEMO_MODE`를 끄고, 체험 계정을 정지하거나 비밀번호를 모두 바꾸세요.
   휴대폰 인증번호(2단계 인증)는 문자 발송 서비스 계약 후 붙여야 합니다.
2. **HTTPS 적용**과 서버 접근 제한 (내부망 또는 VPN 권장)
3. **개인정보 보호**: 건강정보는 민감정보입니다. 개인정보 영향평가, 접근 기록 보관, 암호화, 보관 기간 규정을 검토하세요.
4. **install.php 삭제**, `config.php`의 `INSTALL_KEY` 변경
5. DB 정기 백업
6. 수혜자·담당자 등록/수정 화면 (지금은 설치 스크립트로만 입력)
7. 현장 통신 음영지역(조도면 등)을 위한 오프라인 저장 후 전송 기능
